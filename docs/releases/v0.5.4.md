# v0.5.4 — 背景一定改得动

修的是用户反复反馈的那句「背景的颜色还是改不了」。

## 症状

拾取会话滚动区 `div.8VlCIm_scroll` 后，面板里**只有「文字」一行** —— 没有背景行，于是无从下手。

## 根因

背景行原本靠三种「猜」：元素自己画背景 / 伪元素画 / 发现某个祖先或铺满的直接子元素在画。
那个元素层级更深（DSH 会话视图 + 插件包装夹出来 8～10 层），而祖先探测只走 6 层；
直接子元素里又没有铺满 ≥85% 且上色的 —— 三条都不成立，面板就一行背景都不给。

## 这一版

* **本元素透明时也一定给一行背景**（标签：`背景 · 当前透明`）。给透明元素自己上背景色是可见的
  （画在祖先之上），所以这一行始终可用。
* 祖先探测 6 → 12 层；铺满子元素扫描 10 → 20 个。
* 修掉「空位」陷阱：0% 不再被当成「用户想要的透明度」。在 `rgba(0,0,0,0)` 的行里输入颜色、
  或从这一行打开编辑器，都会按不透明起手 —— 否则写出的是 `rgba(r,g,b,0)`，屏幕上什么都没变。

## 实测

| 操作 | 结果 |
| --- | --- |
| 拾取透明容器 | 出现 `背景 · 祖先 …` / `背景 · 当前透明` / `文字`（修前只有 `文字`） |
| 在「当前透明」行输入 `#123456` | 规则写入该元素，计算背景 `rgb(18, 52, 86)` |
| 从该行打开编辑器 | 起手 `A=100%`；拖 R → `rgb(90, 52, 86)` |
| 在「祖先」行改色 | 只改祖先（`[data-phase="hero"]` → `rgb(63, 164, 106)`），被点元素保持透明 |
| 覆盖式子元素 / 自己画背景的元素 | 行数与 0.5.3 一致，没有回归 |

装法同 README；已经装过的刷新页面（F5）即可，面板标题应显示 `v0.5.4`。
